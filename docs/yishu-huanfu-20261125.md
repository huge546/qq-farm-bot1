# 2026-11-26 更新：请求明文已解出，卖出链路跑通

上面的「待确认」已全部解决或被证伪。核心突破是**请求体可以解密**。

## 破解请求明文的方法

客户端请求体虽然是密文，但仓库自带同一套 tsdk，`core/src/utils/crypto-wasm.ts` 暴露了 `decryptBuffer`。只要 `bindUser(openid)` 之后，就能把抓到的请求密文解回明文。

```js
const cw = require('/app/core/dist/utils/crypto-wasm');
(async () => {
    await cw.initWasm();
    await cw.bindUser('<账号 openid>');           // 与抓包账号一致
    const out = await cw.decryptBuffer(Buffer.from('<f2 密文 hex>', 'hex'));
    console.log(out.toString('hex'));
})();
```

在运行中的容器里执行（`decryptBuffer` 只依赖 wasm 与 openid，不依赖在线会话）：

```bash
docker cp /tmp/dec.js qq-farm-bot:/tmp/dec.js
docker exec qq-farm-bot node /tmp/dec.js
```

首次验证用的是抓包帧 `C:\qq-farm-capture2\ws_000635.bin`（op93 请求）：

```
密文 e929be80ba30e3debec7e7985fa3a538513e32
  ↓ decrypt
08 dc8590c607 10 5d 8a0c 08 08ec a1c79e04 1001
```

逐段解析：

| 片段 | 含义 |
| --- | --- |
| `08 dc8590c607` | `activity_id = 2026111708` |
| `10 5d` | `operate_type = 93` |
| `8a 0c` | tag = field **193**，wire 2 |
| `08` | 长度 8 |
| `08 ec a1 c7 9e 04` | 载荷 field 1 = **gid = 1137823980** |
| `10 01` | 载荷 field 2 = **count = 1** |

结论：

```text
op93 载荷(field 193) = { 1: gid, 2: count }
```

之前按 `{1: count}` 构造，服务端把数量当 gid 解析，稳定返回 `1034005`。补上 gid 后立即成功。

## op98 = 刷新今日收购价

跨天后（每天 00:00 结算）`shop.f1 / f2 / f3 / f4 / f6` 全部归零，此时卖出会按 0 价成交。必须先发一次：


这是每日自动化的必要前置步骤。

## 补齐方式（推荐）

用同一套 mitmproxy 链路重抓一次，按固定顺序操作，时间戳即可把请求切开：

1. 打开活动页 → 领取红薯种子
2. 点「分享」到好友或群（触发分享暴击）
3. 卖出 1 个蜜薯（不要一次全卖）
4. 兑换最低价商品一次
5. 领取任意可领奖励

每一步之间停 2~3 秒即可，回包里的 `operate_type` 与 `130` 状态变化会直接给出映射。
